## 1. File Watcher Implementation

The filesystem watcher ([`src-tauri/src/filesystem/watcher.rs`](file:///home/sumeet/Documents/writers-tool/Swrite/src-tauri/src/filesystem/watcher.rs)) wraps the native cross-platform `notify` crate:

- **Recursive Project Monitoring**: Recursively watches `project_root`.
- **Backend Internal Filter**: Drops events generated by `.swrite/`, `.git/`, and temporary `.tmp` atomic write buffers.
- **Debounced Delivery**: Gathers filesystem events with a 100ms debounce window to prevent notification floods.
- **Tauri Event Emission**: Emits `swrite:fs-event` over the webview channel with typed payloads (`FileCreated`, `FileModified`, `FileDeleted`, `FileRenamed`).
- **Trigger, Not Canonical Authority**: Watcher events trigger verification; the engine always reads the actual disk state and compares content hashes before modifying runtime state.

## 2. Three-Way Reconciliation Engine

When a file is modified externally while open in Swrite, [`reconcile_content`](file:///home/sumeet/Documents/writers-tool/Swrite/src-tauri/src/filesystem/reconciliation.rs#L34-L113) compares the Base, User (in-memory editor state), and Disk contents:

| Condition | Classification | Action |
| :--- | :--- | :--- |
| `User == Disk` | `Identical` | No action needed. |
| `User != Base && Disk == Base` | `UserOnlyChanged` | Safe to write user buffer to disk. |
| `User == Base && Disk != Base` | `ExternalOnlyChanged` | Safe to auto-reload disk content into memory. |
| `User != Base && Disk != Base` | `BothChangedConflict` | Conflict detected; generates `ConflictDetails` struct for author resolution. |
| `Disk is None` | `DeletedOnDisk` | Author notified that file was deleted externally. |
